# QQ 官方图文卡片

`astrbot_plugin_official_cards` 为 AstrBot 插件回复和订阅消息提供 QQ 官方 Markdown 图文、临时图片地址、功能菜单及点击回调按钮。当前版本为 **1.0.14**。

本插件负责展示与消息发送。光遇、王者营地、RConsole、签到等业务功能仍由各自插件提供，需要分别安装和配置。

## 安装与前置条件

1. 在 AstrBot 插件管理中安装本仓库并安装 `requirements.txt` 中的依赖。
2. 配置并连接 AstrBot 的 QQ 官方适配器。目前图文发送及点击回调的完整路径针对 `qq_official` WebSocket 适配器实现；不能仅凭平台名称推断 Webhook 适配器具有相同能力。
3. 准备自己控制的公网 HTTPS 图片地址，将其中的 `/api/file/` 路径转发到 AstrBot 的文件接口。
4. 在插件设置中填写自己的 `public_base_url`，例如 `https://example.com`，然后重载插件。该值是地址前缀，不含 `/api/file/`、查询参数或片段。
5. 宿主系统应有可用的中文字体。可安装 Noto Sans CJK，或通过 `OFFICIAL_CARDS_FONT_PATH` 指定字体文件；无可用中文字体时，新菜单图可能无法生成。

Python 第三方导入为 Pillow（`PIL`）、aiohttp、Starlette 和 QQ SDK（`botpy`，安装包名 `qq-botpy`）。AstrBot API 由宿主提供，使用宿主的依赖约束安装这些包。本插件还使用 AstrBot 的 QQ 官方适配器、文件令牌服务和控制台路由，升级 AstrBot 后需要重新验证兼容性。

## 图片地址

发布的图片 URL 形如 `https://example.com/api/file/<临时令牌>`。QQ 服务必须能够经公网 HTTPS 读取图片；只在本机可达的地址无法用于官方图文。

反向代理应保留 `/api/file/` 路径，并允许该图片接口的 GET 和 HEAD 请求返回图片。HEAD 支持仅针对本插件发布的图片令牌。不要将图片路径转发成登录页或其他 HTML 页面。

本插件只为本次由机器人发出的图片建立临时访问能力。图片链接在有效期内可重复读取；达到数量限制、缓存上限或有效期后，旧链接可能失效。图片地址有效期不代表 QQ 消息发送或回调权限的有效期。

## 配置

| 设置 | 用途 |
| --- | --- |
| `enabled` | 启用图文适配，默认开启 |
| `public_base_url` | 自己部署的 HTTPS 图片地址前缀，安装后必须填写 |
| `enable_keyboard` | 启用按钮，默认开启 |
| `image_ttl_seconds` | 图片有效期，默认 21600 秒，允许 60–86400 秒 |
| `max_image_tokens` | 保留的图片访问令牌数，默认 256，允许 8–512 |

## 菜单与按钮

发送 `/功能菜单` 或 `/官方菜单` 打开入口；发送 `/功能菜单 光遇`、`/功能菜单 王者`、`/功能菜单 音乐` 等进入分类。

光遇、签到、王者、音乐及资源分类优先通过原插件的帮助命令展示已有帮助图。已有图片和查询结果继续使用原内容；只有适用的纯文字菜单才会生成新菜单图。业务插件未安装时，分类入口不会补出其业务功能。

在 QQ 官方群聊和私聊中，按钮点击由 interaction 回调进入正常消息处理流程，机器人直接回复。按钮状态绑定请求者、适配器及群聊或私聊目标，并有有效期；重载后旧按钮可能需要重新打开。

参数完整且已列入允许范围的命令可以直接执行。需要玩家编号、链接、关键词或其他参数的按钮会先显示语法和示例，由用户填写后发送；点击本身不会替用户补参数。管理员、私聊、账号归属和各业务插件的权限检查仍独立生效。菜单显示某个入口不代表已获业务操作权限。

每人独立菜单：群聊按钮仅允许菜单发起者使用，服务端还会核对点击者、适配器和目标。其他人请自行发送帮助命令打开自己的菜单。

按钮结果确认送达后，尝试撤回这次点击的来源卡片；翻页和功能按钮均使用此规则。等待提示不会撤回来源，结果发送失败时保留来源。仅使用机器人已确认的发送回执，绝不根据回调提供的消息编号删除任意消息。超过安全时间窗口（115 秒，为 QQ 两分钟限制留出边界）的卡片不再撤回。普通手动输入和主动推送不会触发此逻辑；重载后请重新打开菜单。

按钮按两列、每页最多十个组织，较长菜单分页展示。QQ 明确拒绝按钮能力时会移除按钮继续发送图文；明确拒绝 Markdown 时沿用原消息组件发送。超时、限频及未明确分类的接口错误不会触发重复发送。发送确认需要有效的 QQ 消息回执。

## 官方 QQ 能力范围

图文、按钮、群聊、私聊、频道和主动发送可用性受 QQ 官方机器人权限、接口能力、消息时机及审核要求影响。本插件不提供或提升这些权限。频道按钮不使用群聊和私聊的同一套点击回调。

视频及其他媒体沿用 AstrBot 的原有解析和上传路径；合并转发中的文字和图片按原顺序展开，无法保证与其他平台的转发样式完全一致。其他平台继续使用原平台的消息发送路径。

## 验证

离线测试使用模拟的 AstrBot 和 QQ API 边界及临时图片，不需要真实机器人凭据。从包含插件目录的父目录运行：

```text
python -B astrbot_plugin_official_cards/tests/run_unit.py
```

测试覆盖图文与按钮发送、明确的能力拒绝、回执确认、重复发送限制、权限菜单和图片令牌边界。离线测试不会证明实际 QQ 权限、公网图片可达性或真实账号发送成功。持续集成建议见 [CI.md](CI.md)。跨插件与宿主源码测试需要另行准备对应仓库，详见 CI 说明；不计入单仓库测试。
